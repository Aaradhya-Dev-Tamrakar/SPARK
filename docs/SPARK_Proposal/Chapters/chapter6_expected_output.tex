\chapter{Expected Output}\label{chap:expected_output}

The project transitions from foundational research and simulation to physical cohort data collection, model fine-tuning, and end-to-end clinical validation.

\section{Tangible Deliverables}

\subsection{Hardware \& Mechanical Deliverables}

\begin{enumerate}
    \item \textbf{Functional Wearable Edge Node}: Ergonomic dorsal wrist wearable incorporating the ESP32-S3 microcontroller, MPU6050 6-axis IMU, 1100\,mAh Li-ion battery, and TP4056 USB-C charging module.
    \item \textbf{TPU 95A DFM Enclosure}: Robust 3D-printed enclosure with $3\text{--}4$\,mm solid walls, threaded brass heat-set inserts (M2/M2.5) to prevent screw stripping, and a dual-zone retention strap.
    \item \textbf{Benchmarked Companion Gateway}: Intel Core Ultra 7 155H companion laptop utilizing OpenVINO hardware acceleration (CPU AVX-VNNI $0.131$\,ms, Arc GPU $0.200$\,ms, AI Boost NPU $0.383$\,ms).
    \item \textbf{Power Profile Validation}: Documented operating current draw ($35\text{--}60$\,mA event-gated BLE) delivering $16\text{--}28$\,hours of continuous protection.
\end{enumerate}

\subsection{Software \& Machine Learning Deliverables}

\begin{enumerate}
    \item \textbf{Edge Firmware Pipeline} (ESP-IDF/PlatformIO C++): Continuous 200\,Hz IMU sampling, Layer~1 software threshold pre-filter ($|a|>2.5$\,g, $>300$\,ms), and on-device TFLite Micro inference.
    \item \textbf{Quantized INT8 1D CNN Model}: Ultra-compact \textbf{18.5\,KB} FlatBuffer and C-header array (\texttt{spark\_cnn\_int8.h}) trained under leakage-free subject-grouped splits on 38,426 SisFall windows ($87.81\%$ sensitivity, $0.9185$ AUC-ROC).
    \item \textbf{Companion Gateway Suite}: Asynchronous GATT BLE receiver (\texttt{BleReceiver}), gradient-based XAI explainer (\texttt{CnnShapExplainer}), and automated one-page clinical PDF generator (\texttt{ReportLab}) verified across 4 fall archetypes.
    \item \textbf{Zero-Dependency REST Server \& Web Dashboard}: Standalone HTTP server (\texttt{gateway/server.py}) providing live incident monitoring and PDF downloads for care staff.
    \item \textbf{Nepal Cohort Wearable Dataset \& Protocol}: Standardized 34-activity protocol (15 falls, 19 ADLs) across $N=12\text{--}20$ volunteers at KEC, published as an open-access regional benchmark.
    \item \textbf{Comprehensive Open-Source Repository}: Complete codebase with 48 automated test suites passing cleanly, CI validation scripts, and reproducibility documentation.
\end{enumerate}

\section{Future Research Extensions \& Academic Roadmap}

SPARK defines three architectural extensions for the final thesis defense and post-thesis publication:

\subsection{Multi-Modal Vision-IMU Fusion}

While SPARK's primary wearable node operates autonomously, indoor residential settings can benefit from late vision-IMU fusion. A stationary ambient sensor node (e.g., ESP32-CAM or gateway webcam) is activated only upon wearable Layer~1 \texttt{PRE\_FALL} notification, running lightweight pose estimation to eliminate false positives from dropping the device or vigorous slapping motions without compromising bathroom/bedroom privacy during normal ADLs.

\subsection{Aquatic Distress \& Drowning Detection Roadmap}

The 6-axis edge kinetic pipeline can be extended to aquatic safety and drowning mitigation by adapting temporal feature extractors:
\begin{itemize}
    \item \textbf{Stroke Cadence Monitoring}: Continuous cyclic analysis ($0.4\text{--}1.6$\,Hz) tracking normal swimming biomechanics.
    \item \textbf{Instinctive Drowning Response (IDR) Detection}: High-frequency vertical arm pressing ($>2.5$\,Hz with no forward displacement) triggering distress flags.
    \item \textbf{Submersion Immobility Timeout}: Vertical orientation stillness exceeding $15$\,s triggering emergency acoustic/radio alarms.
\end{itemize}

\subsection{Client-Side Encrypted Telemetry Storage}

To maintain strict patient privacy and compliance with international health data regulations (HIPAA/GDPR principles), longitudinal motion features are encrypted on the companion gateway using client-derived AES-256 keys before cold storage or optional decentralized backup.
