# SPARK — Literature Review Matrix

Source: `docs/SPARK_Proposal/BackPages/references.bib` + `docs/SPARK_Proposal/Chapters/chapter2_literature.tex`.

| Title / Author / Date | Conceptual Framework | Research Question(s) / Hypotheses | Datasets | Methodology | Analysis & Results | Conclusions | Implications for Future Research |
|---|---|---|---|---|---|---|---|
| **Comparison of Low-Complexity Fall Detection Algorithms for Body-Attached Accelerometers**<br>Kangas et al., 2008 | Threshold-based fall detection via resultant-magnitude spike detection | How does sensor placement affect threshold-algorithm sensitivity/specificity trade-offs? | Hip and wrist IMU data | Empirical comparison of multiple threshold algorithms across placements | Sensitivity 73–95% depending on placement; false-positive rate >30% on vigorous ADLs | Single-stage threshold triggers on any rapid motion, not falls specifically | Motivates two-layer gating (Layer 1 threshold + Layer 2 CNN) instead of threshold-only detection |
| **Evaluation of a Threshold-Based Tri-Axial Accelerometer Fall Detection Algorithm**<br>Bourke & Lyons, 2008 | Dual-axis threshold detection | Can a dual-axis threshold method improve on single-axis sensitivity? | Tri-axial accelerometer trial data | Threshold algorithm evaluation on axis-pair combinations | 96% sensitivity; specificity poor on sit-to-stand transitions | Even improved threshold methods cannot separate falls from similar-magnitude ADLs | Confirms need for a learned classifier stage beyond threshold gating |
| **SisFall: A Fall and Movement Dataset**<br>Sucerquia et al., 2017 | Standardized benchmark dataset for fall-detection evaluation | Can a public, diverse fall/ADL dataset enable reproducible cross-study comparison? | SisFall: 15 fall types, 19 ADL types, 38 subjects | Dataset collection and public release protocol | Widely adopted as the standard feature-based classifier benchmark | A shared benchmark materially improves reproducibility across fall-detection literature | SPARK's primary training dataset (paired with self-collected Nepal-context data) |
| **Deep Convolutional Neural Network for Fall Detection Using Inertial Sensor Data from Wearable Devices**<br>Nho, Lim & Kwon, 2021 | 1D CNN on raw IMU time-series, no manual feature engineering | Can a compact CNN match or exceed feature-based classifier accuracy within an embeddable size budget? | UCI MHEALTH + SisFall combined | 1D CNN architecture search, trained/evaluated on combined dataset | 97.2% sensitivity, 98.1% specificity; model fits in 150 KB | Deep learning on raw IMU streams outperforms hand-crafted-feature classifiers | Deployed on Raspberry Pi 3, not a resource-constrained MCU — direct motivation for SPARK's on-device TFLite Micro target |
| **LSTM-Based Fall Detection System Using Wearable Sensors**<br>Wang et al., 2020 | LSTM sequence model on continuous IMU streams | Does temporal-sequence modeling improve fall detection over frame-based CNN classification? | Continuous wearable IMU streams | LSTM architecture trained on time-series windows | Accuracy comparable to CNN approaches | Recurrent architectures capture temporal fall dynamics effectively | Inference latency unsuitable for real-time embedded detection — informs SPARK's CNN-over-LSTM choice for the MCU stage |
| **TensorFlow Lite Micro: Embedded Machine Learning for TinyML Systems**<br>David et al., 2021 | TFLite Micro runtime for INT8-quantized inference on microcontrollers | Can CNN inference run reliably within sub-320 KB RAM on Cortex-M4-class hardware? | Keyword-spotting and gesture-recognition task data | Runtime benchmarking of INT8-quantized models on constrained MCU hardware | Establishes feasibility of INT8-quantized CNN inference under 320 KB RAM | TFLite Micro is a viable production path for on-device deep learning at MCU scale | Directly adopted as SPARK's inference runtime (ESP32-S3 + TFLite Micro CNN) |
| **Microcontroller-Based Fall Detection for Elderly Monitoring Using a Threshold-Gated Classifier on Arduino Nano 33 BLE Sense**<br>Kumar, Sharma & Singh, 2022 | Threshold-gated classifier deployed on real microcontroller hardware | Can a gated architecture run entirely on a low-cost MCU without server offload? | Self-collected IMU data on Nano 33 BLE Sense | Threshold-gate + classifier deployed and evaluated on-device | Demonstrates a working gated architecture on real MCU hardware | On-device gating is hardware-feasible on sub-\$5 microcontrollers | Did not combine on-device TFLite Micro CNN inference with gating or provide explainability — the exact gap SPARK closes |
| **A Unified Approach to Interpreting Model Predictions (SHAP)**<br>Lundberg & Lee, 2017 | Cooperative game-theoretic feature-attribution framework | Can a single, theoretically consistent method attribute per-feature contribution across arbitrary model types? | N/A (framework, evaluated across multiple model/domain benchmarks) | Shapley-value derivation + unification of prior attribution methods (LIME, DeepLIFT, etc.) | SHAP values provide the only attribution method satisfying local accuracy, missingness, and consistency simultaneously | SHAP is the theoretically grounded standard for model explainability | Adopted as SPARK's explainability layer (per-event SHAP attribution surfaced to caregivers) |
| **Interpretation of Electrocardiogram Heartbeat by CNN and GRU**<br>Yao et al., 2021 | SHAP applied to a real clinical CNN+GRU classifier | Does SHAP attribution provide clinically meaningful interpretability for a health-AI CNN classifier? | ECG heartbeat classification dataset | CNN+GRU model trained, SHAP applied post-hoc to explain per-beat classification | SHAP attribution highlighted physiologically plausible waveform regions driving classification | SHAP generalizes usefully from generic ML benchmarks to real clinical deep-learning models | Confirms the explainability gap: no published wearable fall-detection system applies SHAP at the per-event level — SPARK's specific contribution |

## Notes
- 9 papers reviewed — meets the guideline's "minimum 5" for literature review submission.
- `who2007falls`, `cbs2021nepal`, and `banos2014mhealthdroid` excluded from the matrix: WHO/CBS entries are context-setting statistical/regulatory sources (population and falls-epidemiology background), not compared research methodologies; `banos2014mhealthdroid` is a data-collection-framework citation not discussed as a compared approach in `chapter2_literature.tex`.
- Row order and grouping (threshold → ML → deep learning → TFLite Micro → explainability) follows the section structure already used in `chapter2_literature.tex`.
